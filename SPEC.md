# ТЗ: веб-приложение «Московский родник»

Документ для Claude Code. Прочитай целиком перед началом работы, затем составь план и иди по приоритетам.

## 0. Контекст и срок

«Московский родник» — заявка на Экологическую премию Правительства Москвы 2026, номинация
«Цифровизация экологических решений». Приём заявок заканчивается **31 октября 2026**. Рабочая версия по
публичной ссылке нужна **к вечеру 30 октября**. Поэтому: сначала работающее ядро (P0), потом эффекты.
Любое решение, которое экономит время без потери качества для пользователя, — правильное.

**Суть.** Приложение поверх открытой базы родников Москвы (data.mos.ru, набор 2454 «Состояние родников
(за исключением микробиологических показателей качества воды)»). Жители видят родники на карте, читают
понятную карточку с официальными анализами и оставляют отметки о реальном состоянии родника. Департамент
природопользования получает от горожан данные, которых нет в базе: течёт ли родник, верна ли точка на карте,
какие родники реально посещают (это помогает выбрать, где брать пробы в первую очередь).

**Факты о данных** (выгрузка от 17.04.2026, см. `data/source/springs.geojson`):
- 258 родников (в исходном наборе 397 строк: строка = родник × год анализа).
- Последний статус: превышения по химии — 108, превышений нет — 63, пробы не отбирались — 87.
- 69 родников не проверялись ни разу, у 46 последний анализ в 2017–2024 годах.
- Анализ только химический, микробиологии нет. Роспотребнадзор рекомендует пить воду из родников только после кипячения.
- У 8 родников координаты в разные годы расходятся больше чем на 100 м.

**Принцип подачи.** Приложение про состояние и безопасность родников, а не «где набрать вкусной воды».
Нигде не обещать, что вода чистая. На каждой карточке — блок «О воде» с честными оговорками.

## 3. Данные

### 3.1. JSON-база

Правило пользователя: **папка — сущность, JSON-файл в папке — экземпляр сущности с атрибутами.**

- Корень базы — переменная окружения `DATA_DIR` (по умолчанию `./data`).
- Запись атомарная (`write-file-atomic`), все записи в одну сущность идут через очередь (без гонок).
- При старте сервер читает все сущности в память и строит индексы (по `spring_id`, `user_id`). Чтение из памяти,
  запись — в память и на диск.
- Валидация каждой сущности через `zod`. Невалидный файл при старте — предупреждение в лог, файл пропускается.
- Идентификаторы новых записей — ULID или UUID v7.

Сущности:

| Папка | Файл | Назначение |
|---|---|---|
| `springs/` | `<slug>.json` | родник: официальные данные + история анализов (пишет только синхронизация) |
| `datamos/` | `raw-<YYYY-MM-DD>.json`, `sync-state.json` | сырые снимки набора и состояние синхронизации |
| `users/` | `<id>.json` | пользователи |
| `observations/` | `<id>.json` | отметки о состоянии |
| `photos/` | `<id>.json` | метаданные фото (сами файлы — в `uploads/photos/`) |
| `subscriptions/` | `<user_id>__<slug>.json` | «Слежу за родником» |
| `hidden/` | `<entity>__<id>.json` | скрытый модератором контент |

`slug` родника — латиницей: сокращение округа + номер, например `zao-8`.
Соответствие: ЦАО→cao, САО→sao, СВАО→svao, ВАО→vao, ЮВАО→yuvao, ЮАО→yuao, ЮЗАО→yuzao, ЗАО→zao,
СЗАО→szao, ЗелАО→zelao, НАО→nao, ТАО→tao. Поле `spring_id` (кириллица, «ЗАО-8») сохраняй — на него ссылаются образцы.

### 3.2. Схемы

`springs/<slug>.json`:
```
{ slug, spring_id, number, name, adm_area, district, location, lon, lat,
  status: "exceed"|"ok"|"not_sampled", status_year, last_sample_year|null, never_sampled,
  coord_drift_m, history: [{year, status}], source_global_ids: [], updated_from_source_at }
```

`users/<id>.json`:
```
{ id, display_name, avatar_id, device_token_hash, fingerprint_hash|null,
  created_at, last_seen_at, name_changed_at|null, is_sample: false }
```

`observations/<id>.json` (совместимо с образцами, которые уже лежат в `data/observations/`):
```
{ id, spring_id, user_id, kind, value, comment|null, photo_ids: [], created_at,
  is_sample: false, affects_map: true,
  location?: { lon, lat } }            // только для kind = location_check
```
`kind` и допустимые `value`:
- `flow`: `flowing` | `weak` | `frozen` | `dry`
- `access`: `cleared` | `icy` | `blocked`
- `cleanliness`: `clean` | `litter` | `damaged`
- `visit`: `visited`
- `location_check`: `confirmed` | `wrong` (при `wrong` — точка, которую пользователь указал на карте)

`photos/<id>.json`:
```
{ id, spring_id, user_id, file, width, height, season, caption|null, created_at, is_sample: false }
```

### 3.3. Синхронизация с data.mos.ru

- Ключ: `DATAMOS_API_KEY` из `.env.local` (локально) или переменной окружения (на сервере).
- **Сначала проверь формат API.** Открой документацию apidata.mos.ru, напиши маленький скрипт-пробу
  `server/scripts/probe-datamos.ts`, сделай один запрос к набору 2454 (строки и количество строк), посмотри
  реальную структуру ответа (поля могут лежать во вложенном объекте вроде `Cells`). Только после этого пиши синхронизацию.
- Логика сведения — как в `build_springs_geojson.py`: группировка по (округ, номер), координаты последнего года,
  статус по последнему году, `last_sample_year` — последний год с реальной пробой, `coord_drift_m`, история.
  Напиши тест, что на сырой выгрузке из `data/source/` результат совпадает с `springs.geojson` по количеству
  и статусам.
- Запуск: при старте сервера (в фоне, не блокируя старт) и затем раз в сутки. Пагинация, таймауты, 3 повтора.
- Если API недоступен или ответ странный (например, родников стало меньше 200), **ничего не перезаписывать**:
  работать на последнем удачном снимке, записать ошибку в `datamos/sync-state.json`.
- При первом старте, если `springs/` пустая, заполнить её из `data/source/springs.geojson`.

### 3.4. Агрегаты для карты

Для каждого родника сервер считает (только по записям с `is_sample: false`, `affects_map: true`, без скрытых):
- `user_flow`: последнее значение `flow` за 14 дней, иначе `unknown`;
- `user_access`, `user_cleanliness`: последнее значение за 14 дней, иначе `unknown`;
- `visits_30d`: число отметок `visit` за 30 дней;
- `photos_count`, `observations_count`, `last_activity_at`;
- `frost_level` — давность официальных данных: `last_sample_year` = 2025 → 0; 2022–2024 → 1; 2017–2021 → 2;
  никогда → 3.

## 4. API

Все ответы — JSON, ошибки в формате `{ error: { code, message } }` с русским `message`.

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/springs` | FeatureCollection всех родников: официальные поля + агрегаты из 3.4 |
| GET | `/api/springs/:slug` | карточка: родник, история анализов, отметки (новые сверху), фото, подписан ли текущий пользователь |
| POST | `/api/session` | вход/регистрация, см. раздел 5 |
| GET | `/api/me` | текущий пользователь |
| PATCH | `/api/me` | смена имени |
| POST | `/api/springs/:slug/observations` | новая отметка |
| POST | `/api/springs/:slug/photos` | загрузка фото (multipart) |
| PUT / DELETE | `/api/springs/:slug/subscription` | следить / не следить |
| GET | `/api/me/subscriptions` | мои родники и что изменилось с прошлого визита |
| GET | `/api/stats` | счётчики **без образцов**: пользователи, отметки по видам, фото, родники с отметками |
| GET | `/api/export/springs.geojson` | обогащённый набор: официальные поля + агрегаты (для Департамента) |
| POST | `/api/admin/hide` | скрыть запись (`X-Admin-Token` = `ADMIN_TOKEN`) |
| GET | `/api/health` | статус, время последней синхронизации |

Ограничения на пользователя: 30 отметок в час, 10 фото в час, смена имени не чаще 5 раз в сутки.
Плюс общий лимит по IP. Простое ограничение в памяти достаточно.

Фото: принимать JPEG/PNG/WebP/HEIC до 10 МБ; через `sharp` повернуть по EXIF, уменьшить до 1600 px по длинной
стороне, сохранить WebP, **удалить все метаданные, включая GPS**; превью 400 px. Отдавать статикой из
`uploads/photos/` (внутри `DATA_DIR`).

## 5. Пользователь без регистрации

- При первом визите клиент генерирует случайный `device_token` (хранится в `localStorage` и в cookie) и считает
  отпечаток браузера. На сервер отправляются `device_token` и **хеш** отпечатка, сырые компоненты отпечатка
  не передаются и не хранятся. Сервер хранит только хеши (SHA-256 с солью из `SESSION_SALT`).
- Поиск пользователя: сначала по `device_token`, если не найден — по хешу отпечатка (восстановление после
  очистки хранилища), иначе создаётся новый.
- Сессия — подписанная httpOnly cookie.
- Имя по умолчанию: «Гость-<животное> <4 цифры>», например «Гость-снегирь 4854». Животное и аватар берутся
  детерминированно из `web/public/avatars/avatars.json` по хешу.
- Смена имени: 2–32 символа, буквы, цифры, пробел, дефис; нельзя «Образец» и имена, похожие на официальные
  («Мосприрода», «Департамент», «Администратор» и т.п.).
- В подвале ссылка «Конфиденциальность»: что храним (хеш устройства, имя, отметки, фото без метаданных) и что нет.

## 6. Интерфейс

Язык интерфейса — русский. **Никаких эмодзи** нигде в интерфейсе и коде разметки. Иконки — только `lucide-react`
и ассеты из `web/public`.

### 6.1. Главный экран (альбомная ориентация, ширина ≥ 1024 px)

Экран разделён вертикальной линией по центру: **слева панель, справа карта.**

Левая панель (сверху вниз):
1. Шапка: знак и название «Московский родник», справа — аватар и имя пользователя (клик → смена имени).
2. Строка поиска: по названию, району, описанию места.
3. Фильтры с числом родников у каждого варианта (пересчитываются на лету):
   - Результат анализа: превышения / превышений нет / не проверялся.
   - Давность анализа: 2025 / 2017–2024 / ни разу.
   - Состояние по отметкам жителей: течёт / слабо / замёрз / пересох / нет свежих отметок.
   - Округ (12).
   - Только с фото.
   - Мои родники (на которые подписан).
4. Сводка по выборке: «Показано 63 из 258» и короткая строка статистики.
5. Список родников выборки (компактный, виртуализация не нужна — 258 строк), клик = как клик по маркеру.
6. Подвал: «О проекте», «Конфиденциальность», «Источник данных: data.mos.ru, набор 2454».
   Фон панели — узор `patterns/topo-contours.svg`.

Правая часть — карта.

Состояние фильтров и открытого родника — в URL (`/?status=exceed&adm=zao`, `/spring/zao-8`), чтобы ссылкой
можно было поделиться.

### 6.2. Узкие экраны (< 1024 px, телефоны)

Карта на весь экран, панель фильтров — выезжающая снизу шторка, карточка родника — тоже шторка снизу.
Эксперт может открыть ссылку с телефона, поэтому это обязательно, хоть и без лишних эффектов.

### 6.3. Карта

- Стиль OpenFreeMap (проверь актуальные адреса стилей), перекрашенный под токены: днём светлая «бумага» snow,
  контуры ink. Подписи — по-русски, если стиль поддерживает `name:ru`.
- 3D-дома (`fill-extrusion`) с зума 15.
- Маркеры — `symbol`-слой с иконками из `web/public/markers/png@2x/`:
  форма по статусу анализа, поверх — иней `frost-1..3` по `frost_level`, сбоку — значок состояния `state-*`
  по `user_flow`. Выбранный маркер — `selected-halo`.
- Родники с `user_flow = flowing` — анимированные круги на воде (см. раздел 2).
- Кластеры на мелких зумах — с цифрой, в стиле токенов.

### 6.4. Эффект смены фильтров

При изменении фильтров:
1. Камера плавно (`fitBounds`, ~900 мс, с отступом под панель) переезжает на границы новой выборки.
2. Маркеры, выпавшие из выборки, сжимаются и гаснут (~300 мс), попавшие — появляются с лёгким «всплытием».
   Делать через `feature-state` и переходы `icon-opacity` / `icon-size`, а не пересоздавая слой.
3. Если выборка пустая — иллюстрация `illustrations/empty/empty-filters.webp` в панели, камера не двигается.

### 6.5. Открытие карточки родника

По клику на маркер или строку списка:
1. Камера пролетает к роднику (`flyTo`: зум ~16, наклон ~55°, небольшой поворот, ~1200 мс).
2. Одновременно левая панель сменяется карточкой: карточка «вырастает» из точки маркера к панели
   (shared-element / масштаб от точки), а поверх неё на ~600 мс лежит текстура инея
   `effects/frost-tile-512.webp`, которая «оттаивает» (растворяется маской от центра к краям).
3. Закрытие (кнопка «Назад» или Esc) — обратная анимация, камера возвращается к прежней выборке, фильтры сохранены.

Содержимое карточки:
- **Шапка:** последнее реальное фото или, если фото нет, одна из иллюстраций `illustrations/card/*`
  (выбор детерминированно по `slug`). Поверх — лёгкие блики `effects/caustics-tile-512.webp` (CSS-анимация, медленно).
- **Название:** имя родника или «Родник № N», район, округ.
- **Как найти:** описание места из базы, координаты, кнопка «Маршрут» (открывает Яндекс Карты с пешим маршрутом
  до точки).
- **О воде** (официальные данные) с пиктограммами из `pictograms/`:
  - статус последнего анализа и год;
  - «Анализ только по химическим показателям», «Микробиология не проверяется»;
  - «Роспотребнадзор рекомендует пить воду из родников только после кипячения» — **всегда**, у любого статуса;
  - если не проверялся — «Пробы не отбирались»;
  - мини-шкала истории анализов по годам.
- **Сейчас у родника** (по отметкам жителей): течёт ли, подход, чистота — с давностью («3 часа назад»)
  или «Свежих отметок нет».
- **Действия:**
  - «Отметить состояние» — быстрый выбор `flow`, `access`, `cleanliness` в одном небольшом окне, необязательный
    комментарий, необязательное фото.
  - «Я был здесь» — отметка `visit` (эффект: капля падает в маркер, круг расходится, счётчик увеличивается).
  - «Добавить фото».
  - «Точка на карте верна?» — да / нет; при «нет» пользователь ставит точку на карте. Для родников с
    `coord_drift_m > 100` этот вопрос показывать заметнее.
  - «Следить за родником».
  - «Поделиться» — копирует ссылку `/spring/<slug>`.
- **Лента:** отметки и фото, новые сверху. Образцы — с плашкой «Образец» (см. 6.8).

При выборе «замёрз» маркер на карте «замерзает»: из центра прорастает кристалл `effects/ice-crystal.svg`
(ветви анимируются по очереди, ~500 мс).

### 6.6. Атмосферные эффекты

- **Снег.** Слой поверх карты: максимальная плотность на зуме ≤ 11, к зуму 14 снег плавно исчезает.
  При открытой карточке плотность снижается вдвое. Снежинки не перехватывают клики (`pointer-events: none`).
- **Время суток.** По `suncalc` для Москвы: день — светлая карта; сумерки — тёплый приглушённый вариант;
  ночь — тёмная тема (`dusk`), маркеры чуть светятся. Переключение плавное.
- **Течение рек (P2).** Реки и ручьи из OSM анимированным пунктиром по направлению течения, только на средних зумах.
  Данные: одноразовый скрипт `server/scripts/fetch-waterways.ts` через Overpass API (с нормальным
  `User-Agent`, при отказе — зеркала), результат коммитится в `data/source/waterways.geojson`.

### 6.7. Правила для эффектов

- Анимации отклика не длиннее 400 мс, ничего не блокирует ввод.
- `prefers-reduced-motion: reduce` → снега нет, круги и иней статичные, переходы мгновенные.
- Анимации на паузе, когда вкладка скрыта.
- Состояние никогда не передаётся только цветом: форма маркера + значок.
- Целевые 60 fps на ноутбуке среднего уровня; на слабых устройствах (`navigator.hardwareConcurrency <= 4`)
  снега в 2 раза меньше.

### 6.8. Образцы

- Образцы (`is_sample: true`) показываются в лентах с плашкой «Образец» и подписью
  «Пример того, как будут выглядеть отметки жителей».
- Образцы **не влияют** на маркеры, фильтры, агрегаты, `/api/stats` и экспорт.
- Как только у родника появляется 3 реальные записи, образцы в его ленте скрываются.

### 6.9. Режим истории (P2)

Кнопка «О проекте» открывает пошаговый рассказ (4–5 шагов), где камера карты следует за текстом:
258 родников → анализ только химический → 69 ни разу не проверялись → у 8 расходятся координаты →
что могут сделать жители. Цифры брать из данных, а не хардкодить.

## 7. Деплой (Northflank)

- `Dockerfile`, многоэтапный: сборка `web/` и `server/`, финальный образ на `node:22-slim`, один процесс
  отдаёт API и статику (`web/dist` + `web/public`), SPA-маршруты (`/spring/*`) отдают `index.html`.
- Порт из `PORT`. Переменные: `DATAMOS_API_KEY`, `DATA_DIR`, `SESSION_SECRET`, `SESSION_SALT`, `ADMIN_TOKEN`,
  `PUBLIC_URL`. Шаблон без значений — `.env.example`.
- `DATA_DIR` должен быть на **постоянном томе** (файловая система контейнера временная). При старте, если том
  пустой, скопировать в него начальное содержимое `data/` из образа (родники и образцы).
- Health check — `/api/health`.
- `DEPLOY.md`: пошагово, что мне сделать в Northflank (сервис из репозитория, том, переменные, порт).
  Сам в Northflank ничего не делай, если у тебя нет к нему доступа.
